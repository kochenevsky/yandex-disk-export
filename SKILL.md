# Как скачивать картинки с Яндекс Диска через ИИ-агента


> **Зачем это появилось.** Скилл сделан во время сбоя Яндекса, когда скачивание с Диска перестало работать. Мы очень надеемся, что Яндекс скоро всё починит и окажется, что мы переживали за свои фото и видео зря. Но остаться в стороне и рисковать мы не могли: на Диске хранится память нашей семьи и нашего детства. Скачивание идёт аккуратно, по несколько файлов за раз, теми же запросами, что и обычный просмотр папок. Надеемся, что оно никак не помешало Яндексу восстанавливать серверы.

> **Ответственность.** Авторы скилла не несут ответственности за поведение Claude с этим скиллом и за последствия (потеря/перезапись файлов, действия в браузере и аккаунтах). Вся ответственность — на пользователе, он должен следить за действиями агента. **Перед стартом обязательно скажи это пользователю** и попроси следить за процессом.

Связка: **вкладка Яндекс Диска в Chrome** (скрипт качает картинки пачками) + **раскладчик в терминале** (переносит скачанное в нужные подпапки) + Claude (запускает, следит, отчитывается).

Скрипты: `~/.claude/skills/yandex-disk-export/scripts/`
- `browser_preview_export.js` — вставляется во вкладку Диска
- `helper_tab.js` — вставляется во вкладки-помощники `N.downloader.disk.yandex.ru`
- `mover_copies.py` — раскладчик на Mac
- `done_folders.py` — список уже скачанных папок, чтобы продолжить после остановки
- `progress_monitor.sh` — сводка прогресса раз в N минут для Monitor (и тревога, если встало)

## Что нужно
1. **Claude Code** на компьютере.
2. **Расширение Claude in Chrome** — официальное расширение Anthropic, через которое Claude Code управляет браузером (открывает страницы, делает скриншоты, выполняет скрипты во вкладке). Ставится из [Chrome Web Store](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn), в нём нужно войти в тот же аккаунт Claude, что и в Claude Code.
3. **Связать Claude Code с браузером** — обычно командой `/chrome` в Claude Code ([инструкция Anthropic](https://code.claude.com/docs/en/chrome)).
4. **Вход в свой Яндекс Диск** в этом Chrome.
5. **Python 3** для раскладчика (на Mac обычно уже есть: `python3 --version`).

Если расширения нет — см. «Ручной режим» в конце: всё то же самое, но скрипт во вкладку вставляет сам пользователь.

**Права доступа (предупредить пользователя заранее):** всё идёт из Терминала, понадобятся подтверждения — разрешения Claude Code на команды и действия в браузере; доступ Терминала к папке/внешнему диску (macOS спросит «доступ к файлам на съёмном томе», иначе — Настройки → Конфиденциальность и безопасность → Файлы и папки / Полный доступ к диску); разрешение расширения на `disk.yandex.ru`; в Chrome — «скачивать несколько файлов» и выключенное «Всегда указывать место для скачивания». Если раскладчик падает с `Operation not permitted` — это права Терминала на диск.

## Что получится (сказать пользователю до старта)
Скачиваются все картинки: jpg/jpeg/png/gif, а RAW (CR2 и др.) и HEIC — их JPEG-превью под именем `<имя>.CR2.jpg`. Всё в той версии, что открывается по правому клику «Открыть картинку в новой вкладке»: **до 1280px по длинной стороне, пересжатые, без EXIF** (даты съёмки/камеры). Для старых маленьких фото это то же разрешение, для современных — заметно меньше (пример: оригинал 28,9 МБ → 853×1280, 0,3 МБ). Видео и прочие файлы так не скачиваются — их пропускаем и считаем. Класть в **отдельную** папку, например `<том>/<Папка> (копии с просмотра)`.

## Куда скачивать
Место назначения (`<DEST>`) задаёт пользователь — любая папка: на Mac (`~/Pictures/Архив`), на внешнем диске (`/Volumes/<имя диска>/Архив`), на сетевом диске. Если не сказал — спросить. Раскладчик переносит файлы из папки загрузок Chrome в `<DEST>`, даже если это разные диски. Проверить, что места хватит: `df -h "<DEST>"` против объёма из описи (шаг 3).

## Как это работает
Вкладка вызывает внутренний API веб-клиента Диска (`/models-v2?m=mpfs/resources`) — то же, что при открытии папки, под логином пользователя. В ответе у каждого фото есть ссылки на превью (`meta.sizes[].url`, берём `XXXL`). Скрипт обходит все подпапки, по 4 файла одновременно скачивает картинки и сохраняет их через Chrome с именем `TMP<папка>_<n>__<имя>`; перед каждой папкой сохраняет карту `TMPMAP_<папка>.json` вида `{"TMP5_12": "Фотографии/Новый год 2016/DSCN2390.JPG"}`. Раскладчик каждые 3 с читает карты и переносит файлы в `DEST/<путь>` под исходными именами.

## Как узнаём структуру папок, количество и названия файлов
Так же, как это делает сам веб-интерфейс Диска при открытии папки: вкладка запрашивает у сервера Яндекса содержимое папки (`POST /models-v2?m=mpfs/resources`, параметры `idContext: '<путь>'`, `amount: 200`, `offset` — листаем страницами по 200). В ответе для каждого элемента: `type` (`dir`/`file`), `id` (полный путь), `name`, `meta.size`, `meta.mimetype`, `meta.sizes` (ссылки на превью). Подпапки ставятся в очередь и обходятся по одной (в ширину), так собирается полное дерево. Ничего не скачивается — только названия, пути и размеры.

В скрипте это `scan()`:
```js
window.__yaExport.scan('/disk/Фотокамера/Мой архив')      // запустить опись (фоном)
JSON.stringify(window.__yaExport.scanStatus())             // папок, файлов, ГБ, разбивка по типам
window.__yaExport.saveManifest()                            // сохранить опись yadisk_manifest.json
```
Большой архив (~200 папок, ~22 000 файлов) описывается за 5–10 минут — Яндекс отдаёт папки по одной.

## Шаги

1. **Спросить пользователя — всегда, до любых действий** (инструментом AskUserQuestion, если он есть, иначе обычным вопросом), даже если кажется, что ответ ясен из контекста:
   - **«Какую папку на Яндекс Диске скачиваем?»** — путь как в Диске, например `Фотокамера/Мой архив`; можно попросить открыть её в Chrome, и взять путь из адресной строки.
   - **«Куда сохраняем?»** — папка на компьютере или внешнем диске (см. «Куда скачивать»). Предложи по умолчанию `~/Pictures/<имя папки> (копии с просмотра)`, а если подключён внешний диск (`ls /Volumes`) — вариант на нём.

   Здесь же: напомни про ответственность (см. начало) и про качество копий (см. «Что получится»). Не начинай, пока пользователь не ответил на оба вопроса. Если это внешний диск — проверь `ls /Volumes`, что он подключён.

2. **Открыть Диск в Chrome** (claude-in-chrome): `https://disk.yandex.ru/client/disk/<путь url-encoded>`, скриншотом убедиться, что залогинен.

3. **Вставить скрипт:** содержимое `browser_preview_export.js` → `javascript_tool`. Сделать опись (`scan` → `scanStatus`) и показать пользователю: сколько папок, файлов, ГБ, какие типы; сверить место в `<DEST>`.

4. **Найти папку загрузок Chrome** (`<INBOX>`): из вкладки сохрани пробный файл
   ```js
   (()=>{const a=document.createElement('a');a.href=URL.createObjectURL(new Blob(['test']));a.download='ya_probe.txt';document.body.appendChild(a);a.click();a.remove()})()
   ```
   и найди: `find ~ /Volumes/<том> -maxdepth 6 -name 'ya_probe*' 2>/dev/null`. Удалить пробный файл. (Chrome может сохранять прямо на внешний диск — тогда место на Mac не нужно.)

5. **Если в `<INBOX>` или `<DEST>` уже лежат файлы** от прошлых попыток — не удалять, переложить в отдельную папку `… — старое` и сказать пользователю.

5a. **Открыть вкладки-помощники — обязательно, без них теряется до ~75% фото.** Многие превью Яндекс отдаёт без CORS-заголовка: со страницы Диска скрипт их не прочитает («Failed to fetch»), а из вкладки на адресе `N.downloader.disk.yandex.ru` — прочитает. Проверено: 2019 год — 56 фото обычным способом и 2 241 через помощников.
   1. Во вкладке Диска: `window.__yaExport.helperButtons()` — появятся 4 кнопки «HELPER 1…4».
   2. Нажми каждую (computer → left_click; найди по скриншоту) — откроются 4 вкладки «Сервис временно недоступен» — так и должно быть, важен адрес.
   3. В каждую вставь `scripts/helper_tab.js` — вкладка станет «ПОМОЩНИК — не закрывать».
   4. Проверь: `window.__yaExport.helpersStatus()` → `ready` и `open` — все 4 адреса.
   5. **Предупреди пользователя:** не закрывать вкладки «ПОМОЩНИК»; Chrome спросит «Разрешить скачивать несколько файлов?» **на каждой** из них — нажать «Разрешить» везде (иначе помощники отчитываются об успехе, а файлы не сохраняются: проверяй рост папки на диске, а не только `okHelper`).

6. **Запустить раскладчик** (Bash, `run_in_background: true`):
   ```bash
   caffeinate -dimsu python3 ~/.claude/skills/yandex-disk-export/scripts/mover_copies.py --inbox "<INBOX>" --dest "<DEST>"
   ```
   Лог: `<родитель DEST>/ya_copies_mover.log`.

7. **Запустить выгрузку:**
   ```js
   window.__yaExport.start('/disk/Фотокамера/Мой архив')
   ```
   Сначала проверь на одной папке, что файлы появились в `<DEST>` в правильных подпапках.

8. **Сводка раз в 15 минут — присылать пользователю сама, без вопроса.** Запусти Monitor (timeout 30 мин, по истечении — сразу перезапусти, пока выгрузка идёт; сводки привязаны к :00/:15/:30/:45, поэтому перезапуск их не сбивает):
   ```bash
   ~/.claude/skills/yandex-disk-export/scripts/progress_monitor.sh "<DEST>" "<INBOX>" 15 20
   ```
   На каждую строку `СВОДКА …` отправь пользователю короткую сводку: сколько картинок на диске и сколько добавилось, по каким папкам, текущая папка и доля успешных из `JSON.stringify(window.__yaExport.status())` (`ok`/`err`, `cur`), и прикинь, когда закончится. На каждой сводке также проверь `status().idleSec` во вкладке: если > 60 с — выгрузка зависла, даже если монитор молчит. На `ВНИМАНИЕ …` — сразу разберись (см. «Если встало») и сообщи. Если пользователь спрашивает «статус» между сводками — сделай такую же сводку немедленно. Когда выгрузка закончена — финальный отчёт и остановить Monitor.

9. **Если встало** (лог раскладчика не растёт 10+ минут) — продолжить с места остановки, см. «Грабли».

10. **Неудачные** (`failedCount`) — превью, которые Яндекс в моменте не отдаёт (в интерфейсе битые миниатюры). Когда `finished: true` — `window.__yaExport.retryFailed()`, можно повторять позже.

11. **Отчёт:** сколько картинок скачано и разложено, сколько не удалось, сколько пропущено (видео/RAW/прочее), где лежит. Остановить раскладчик (`pkill -f mover_copies.py`) и `caffeinate`.

## Несколько папок подряд
Каждой выгрузке — своя метка и свой раскладчик, тогда файлы не перепутаются, даже если идут в одну папку загрузок:
```bash
python3 .../mover_copies.py --inbox "<INBOX>" --dest "<DEST2>" --prefix ANT
```
```js
window.__yaExport.start('/disk/<вторая папка>', {prefix: 'ANT'})
```
Можно запустить вторую сразу после первой: опрашивать `status().finished` первой и тогда стартовать вторую.

## Пользователю на время выгрузки
- вынести вкладки «Яндекс Диск» и «ПОМОЩНИК» в отдельное окно Chrome и не сворачивать его (или добавить сайты в «Всегда сохранять активность» в `chrome://settings/performance`);
- не закрывать и не перезагружать вкладку Диска (после перезагрузки — вставить скрипт заново и снова `start`; уже разложенное перезапишется теми же файлами);
- не отключать диск, куда идёт выгрузка (если внешний);
- не трогать файлы `TMP…` / `TMPMAP_…` в папке загрузок.

## Грабли
- Один вызов `javascript_tool` не держать дольше ~30 с (таймаут CDP 45 с, вкладка подвисает). Всё длинное — фоном внутри страницы, снаружи только `status()`.
- API требует заголовки `Content-Type: application/json` и `X-Requested-With: XMLHttpRequest`; на `{"error":{"code":"CKEY","ckey":…}}` подставить `ckey` как `sk` и повторить (скрипт делает сам).
- Не печатать в чат ссылки из `meta.sizes` / `mpfs/url` — в них токены (инструмент их всё равно блокирует).
- Передать данные из вкладки на `localhost` нельзя (CSP Диска + запрет классификатора) — только сохранение файлов через Chrome.
- **Таймаут на список папки — на каждую страницу, не на весь список.** Яндекс отдаёт содержимое папки страницами по 200 по 1–4 с; в годовых папках с тысячами файлов общий таймаут 30 с срабатывал раньше, и папка считалась пустой (0 скачано, 0 ошибок). Признак: у папки `ok: 0, err: 0`, хотя на Диске в ней есть фото; `status().lsFailed` > 0.
- **«Failed to fetch» — часто НЕ отказ Яндекса, а защита браузера (CORS).** Для многих превью Яндекс не ставит CORS-заголовок, и скрипт со страницы Диска не может прочитать файл, хотя он доступен (в интерфейсе миниатюра видна). Проверено на 2019 году: обычным способом скачалось 56 фото, а со «своего» адреса (`N.downloader.disk.yandex.ru`) — ещё 699. Настоящие отказы Яндекса — `HTTP 434`/`500`, их видно только изнутри такой вкладки. Не делай вывод о доле доступных по первым минутам: в начале папки отказов может быть почти 100%, дальше — меньше. Решение — вкладки-помощники, см. шаг 5a.
- **Не открывать ссылки Яндекса в рабочей вкладке выгрузки** (`a.click()` по ссылке, смена `location`) — вкладка уйдёт со страницы Диска, и выгрузка остановится. Тесты — только в отдельной вкладке. Параметры в ссылках превью подписаны: менять `disposition`/`filename` нельзя — `403 Forbidden`.
- **Фоновая вкладка = замедление, никаких `setTimeout`-пауз в цикле.** Если вкладка Диска не активна в своём окне (пользователь открыл в том же окне другой сайт) или окно свёрнуто, Chrome через ~5 мин растягивает таймеры до раза в минуту. Пауза 150 мс между файлами становится минутной — выгрузка «стоит» (`idleSec` сотни секунд, `visibilityState: 'hidden'`). В скрипте пауз нет. И всё равно попроси пользователя вынести вкладки выгрузки в **отдельное окно** Chrome с активной вкладкой Диска и не сворачивать его; надёжнее — `chrome://settings/performance` → «Всегда сохранять активность на этих сайтах»: `disk.yandex.ru`, `downloader.disk.yandex.ru`. Проверка изнутри: `document.visibilityState`.
- **Таймаут — на весь файл, а не на начало ответа.** Передача может зависнуть посреди файла; если таймер снимается после получения заголовков, `r.blob()` ждёт вечно и выгрузка молча стоит (на практике — 35 мин). В скрипте таймаут покрывает и чтение тела. Признак зависания: `status().idleSec` растёт (> 60 с), `done` не меняется.
- **Таймауты обязательны.** Во время сбоя Яндекс иногда не отвечает и не закрывает запрос: без таймаута все 4 потока зависают и выгрузка молча встаёт (на практике — через ~40 мин). В скрипте: 20 с на файл, 30 с на список папки; зависшие уходят в «неудачные» и повторяются через `retryFailed()`. Признак зависания: `status().done` не растёт несколько минут, а в логе раскладчика нет новых строк.
- **Если выгрузка встала или вкладка тормозит — продолжить с места остановки:**
  1. `window.__yaExport.stop()`, перезагрузить вкладку Диска, вставить скрипт заново.
  2. Получить список уже скачанных папок (папку, на которой встало, исключить — её докачаем):
     ```bash
     python3 ~/.claude/skills/yandex-disk-export/scripts/done_folders.py "<родитель DEST>/_ya_copies_maps" --exclude "<папка, на которой встало>"
     ```
  3. `window.__yaExport.start('/disk/<путь>', {skip: <этот список>})` — скачанные папки пропускаются, но в их подпапки скрипт заходит.
- Вкладка со временем тяжелеет и начинает отвечать с задержкой (вызовы `javascript_tool` падают по таймауту 45 с). Это сигнал сделать перезапуск по шагам выше.
- Запрос размера больше `XXXL` (например `size=10000x10000`) не даёт больше 1280px.

## Ручной режим (без расширения Claude in Chrome)
Работает так же, только вкладкой управляет пользователь, а Claude подсказывает и следит за раскладкой в терминале.

1. Открыть Яндекс Диск в Chrome, войти в аккаунт.
2. Открыть консоль разработчика: **⌥⌘J** (Mac) или **Ctrl+Shift+J** (Windows).
   Chrome может запретить вставку — тогда набрать в консоли `allow pasting` и нажать Enter.
3. Вставить целиком содержимое `scripts/browser_preview_export.js`, Enter.
4. (По желанию) опись архива:
   ```js
   window.__yaExport.scan('/disk/путь/к/папке')
   window.__yaExport.scanStatus()        // повторять, пока finished: true
   ```
5. Узнать, куда Chrome сохраняет загрузки: Настройки Chrome → «Скачанные файлы» → «Папка». Это `<INBOX>`. Там же выключить «Всегда указывать место для скачивания», иначе на каждый файл будет окно.
6. В Терминале запустить раскладчик:
   ```bash
   caffeinate -dimsu python3 ~/.claude/skills/yandex-disk-export/scripts/mover_copies.py --inbox "<INBOX>" --dest "<куда раскладывать>"
   ```
7. В консоли Chrome запустить выгрузку:
   ```js
   window.__yaExport.start('/disk/путь/к/папке')
   window.__yaExport.status()            // прогресс
   window.__yaExport.retryFailed()       // после finished: true — повтор неудавшихся
   ```
   Если Chrome спросит «Разрешить сайту скачивать несколько файлов?» — разрешить.
8. Когда закончено — в Терминале Ctrl+C (остановит раскладчик и caffeinate).
